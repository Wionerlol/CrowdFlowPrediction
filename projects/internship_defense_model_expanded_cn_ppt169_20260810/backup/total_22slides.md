# 01_cover

各位老师好，我汇报的项目是“多源时空数据驱动的城市人流预测与异常预警”。我的实习岗位方向是网约车安全算法，目标是把城市网格流动信息转化为可提前预测、可识别异常、也能进入预警系统的安全信号。下面先用一页概括五个月最终形成的闭环。

# 02_closed_loop

项目不是只训练一个预测模型，而是完成了从数据到服务的完整链路：空间上统一到 1,024 个节点，时间上预测未来 24 小时；异常侧融合统计、重构和预测误差三种证据；工程侧落地 FastAPI、地图 Web 和三级预警。接下来我会解释这个闭环对应的三个连续业务决策。

# 03_business_questions

网约车安全场景可以拆成预知、识别和处置。预知回答未来各区域人流如何变化；识别判断哪些波动超过正常范围；处置则需要给出事件类型、空间位置和预警等级。因此模型分数必须继续加工成业务事件。为了说明工作量，下一页给出按项目投入回溯估算的五个月周期。

# 04_timeline

这条 20 周时间轴是按实际工作量回溯估算，并不是原始周报日期的机械拉伸。前七周主要完成调研、数据清洗、特征和图结构；W7 到 W14 的七周集中在模型训练、选型、消融和多随机种子复验，是投入最大的阶段；之后完成异常检测与系统化落地。接下来展示这些阶段如何共享同一套数据和评估规则。

# 05_pipeline

端到端路线分五层：数据治理生成连续样本，特征工程生成模型输入，预测模型输出 24 小时序列，异常模块生成事件对象，最后由 API 和 Web 提供查询与预警。贯穿全链路的是时间连续、无泄漏、同窗口公平对照、验证集选参和可复现输出。下面介绍这条路线的论文依据。

# 06_research

我调研了图卷积、时空图网络、Transformer、自适应邻接、Spacetimeformer、VAE、异常 Transformer 和 SHAP。最终没有照搬单一论文，而是组合显式图先验、学习型邻接、时间注意力和三路异常证据。需要强调，项目中的 AGFormer 是自主组合实现，不把它描述成同名论文复现。下一页进入数据底座。

# 07_data_foundation

所有信息被对齐到 1,024 个匿名化城市网格和半小时时钟。动态部分是网格流入流出，静态部分包括路网、POI、公交地铁和遥感指标，外生部分包括天气与日历。这里的原型验证基于公开基准，技术方案面向未来经授权、合规的内部数据环境迁移。接下来说明最关键的数据质量问题。

# 08_gap_aware

数据处理中最大的风险是不连续时段被错误拼接。这样的窗口看似完整，实际把缺口两端当成连续历史，会污染训练与测试。我先重建真实时间戳，再过滤跨缺口窗口；切分严格保持时间顺序，scaler 只在训练段拟合。最终测试集保留 4,022 个有效连续窗口。下一页介绍特征与图结构如何进一步审计。

# 09_features_graphs

早期构建了 41 维候选静态特征，覆盖地理、路网、POI、遥感、公共交通和历史统计；经过泄漏审计后，最终保留 33 维静态特征，并配合 7 维时间日历和 2 维流量。图结构也比较了四类候选，最终采用显式空间图和学习型自适应邻接。下一页从统一基线开始说明模型选择。

# 10_baselines

基线比较说明，扩大历史输入对 RNN 有帮助，但仅做时序仍不够。gap-aware LSTM 三个种子的平均 MAE 是 19.4941，而加入时间和静态上下文的 AGFormer 降到 16.9376。由此确定后续主线要同时建模长时依赖与空间传播。下一页是一次重要的架构负结果。

# 11_model_selection

我原本预期 Spacetimeformer 的通用全局注意力会更强，因此逐步对齐了 local/global attention、value/time embedding、encoder-decoder 与 cross-attention。但 1,024 乘 48 的 token 规模迫使全局注意力近似，且规则网格本身具有强邻域先验，所以它仍未超过 AGFormer。下一页展示最终模型如何利用这一结论。

# 12_agformer_architecture

最终 AGFormer 将 48 步流量、时间日历和静态节点特征通过门控融合。时间路径使用两层四头注意力，空间路径并行使用预定义 GCN 和自适应邻接。输出端再加入线性残差，让线性分支守住惯性趋势，非线性分支学习复杂偏差，并对四个随机种子的预测取均值。下一页用消融说明哪些改动真实有效。

# 13_ablation

消融遵循同数据规则和同测试窗口。2×2 门控实验拆开 flow、time、static；日历修复后重新跑基线，避免错误编码带来虚假提升；周期滞后使用相同 3,433 个窗口对照。结论是门控上下文和线性残差有效，而天气、周期滞后和简单多图权重没有形成稳定增益。下一页给出最终预测结果。

# 14_forecast_results

四 seed 集成在 4,022 个测试窗口上取得 24 小时平均 MAE 15.9030，相对原 gated 基线改善 3.82%。第一步预测 MAE 为 11.3019，但随着预测时域扩大，误差持续上升。模型选择在验证集完成；同时，ensemble 的 MAE 最低，而原单模型 RMSE 略低，说明指标存在权衡。接下来进入异常检测。

# 15_anomaly_fusion

异常检测由三条分支组成：3σ 和 IQR 构建统计正常范围；VAE 与 Transformer 自编码器学习 weak-normal 模式；预测分支使用最终 AGFormer 的观测与预测残差。权重 0.70、0.20、0.10 和阈值 0.56 都在验证集选择。超过阈值后，再按时间与空间连续性合并成事件并分类。下一页说明结果与边界。

# 16_anomaly_results

融合方法在弱标签口径下优于单分支，并最终识别 131 个事件。Level-A 的 timestep F1 为 0.4912，事件级 F1 为 0.4819。这里不能把指标说成现实事件检测准确率，因为缺少权威真标签，而且统计规则既参与弱标签也参与融合。为此另做了 50 个事件人工抽样，但它只是一致性检查。下一页看这些事件如何进入系统。

# 17_system

系统把算法结果封装成带时间、空间、类型、严重度和解释字段的事件对象。Batch 与 realtime 微批共用预处理和推理管道，FastAPI 提供热力图、预测和事件查询，Streamlit 页面展示地图、动画和历史统计。131 个事件全部可定位，三级预警分布是一般 110、重要 15、紧急 6。本页保留两处可替换的现场演示素材。下一页介绍解释性分析。

# 18_xai

时间注意力归一化熵为 0.9956，说明聚合后没有只关注少数滞后。TreeSHAP 的代理模型 R² 为 0.9926，其中历史流量贡献 97.43%，日历贡献 2.33%。131 个事件里有 82 个匹配天气或日历候选证据。但注意力、SHAP 和外部信息只能说明相关贡献，不能冒充因果。下一页展示系统性能优化。

# 19_performance

性能优化先测瓶颈再决定方案。共享 full-sequence 推理和批处理后，暖启动 FP32 从 6.416 秒降到 4.613 秒，提升 1.39 倍；进程树 RSS 降低 53.9%，统计缓存把 1.723 秒压到 0.038 秒。FP16 虽通过质量检查，但速度比只有 0.9945，因此不作为部署方案。下一页总结项目亮点与局限。

# 20_highlights

项目亮点可归纳为三点：数据可信，包含 gap-aware 和无泄漏规则；模型可验证，包含双图、门控、残差、严格消融和多 seed；系统可处置，异常结果进入事件分类、地图和三级预警。局限包括公开基准原型、弱标签、离线微批以及缺少新闻与活动真值。下一步是授权数据、人工标签、跨城市迁移、Optuna 和流式部署。

# 21_references

这一页列出主要技术来源。图学习部分参考 GCN、STGCN 与 Graph WaveNet；长时依赖部分参考 Transformer 与 Spacetimeformer；异常和解释部分参考 VAE、Anomaly Transformer、SHAP 与 Optuna。项目价值在于把这些经典方法放到统一规则下做工程组合与实证选择。最后一页回到五个月实习的核心收获。

# 22_closing

五个月实习让我完成了从研究问题、数据规则、模型训练到异常检测、系统服务与性能评估的完整算法工程闭环。最终 24 小时平均 MAE 为 15.9030，形成 131 个融合异常事件，系统优化获得 1.39 倍端到端加速。我的总结是：把城市流动变成可预测、可解释、可处置的安全信号。谢谢各位老师，欢迎提问。
